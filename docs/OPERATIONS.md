# Operations and recovery runbook

PoPify remains mock-only and single-store. No production deployment is authorized by this repository.

- GET /live checks application liveness; GET /ready checks order schema access and an active managed admin where applicable. /health retains its existing database health contract. Readiness is not an end-to-end n8n availability assertion.
- GET /api/ops/status requires an authenticated operator and reports counts, oldest queue age, uncertain approvals and recent persisted worker polls. It contains no customer payloads. A stale poll does not prove the n8n process is down. Poll it through a protected monitor, not a public endpoint.
- Alert on sustained 503 responses, stale worker polls (three minutes), queue growth, oldest-item age, database pressure and unresolved ambiguous actions. Proposed pilot objectives: p95 webhook acknowledgement <=500 ms and normal queue waiting <=120 seconds under an agreed representative workload. Measure both independently.
- Acknowledged deliveries must persist. If n8n is interrupted, leave queued records intact, restore connectivity and verify normal processing and audit events. Never blindly replay an uncertain action.
- For backups, run PostgreSQL pg_dump -Fc under a least-privilege backup identity, encrypt archives using managed encryption and retain offsite according to an approved policy. Preserve n8n state, encryption key, workflow exports and application configuration separately. Restore to an isolated database, apply compatible migrations, revoke all restored sessions, rotate credentials as appropriate, and check persisted delivery, approval and execution history before resuming workers. Do not restore over the live database. External actions must remain disabled until provider state is reconciled.
- The CI-only scripts/verify_restore.sh creates a unique temporary database in a disposable Compose stack, dumps the source, restores the archive, compares business record counts and removes only its own restore database/archive. This is a basic logical restore drill, not offsite/PITR evidence. Stop mutating workers during a manual consistency drill.
- New signed webhook deliveries persist an allowlist of order fields used by PoPify. Full addresses, line items and unrelated notes are excluded. Historical records and approval snapshots are not rewritten. Email, support text and audit evidence remain personal data; establish retention, access and deletion procedures before real data use. OpenAI requests now set store=false; this does not promise zero provider retention or complete anonymization.
- Before staging, verify managed identity and role changes, login limits with trusted proxy configuration, TLS, private worker access, request timeouts, distributed ingress traffic controls, accessible workflows, restore objectives and workload measurements. Do not expose the local n8n editor. Before real data, approve retention, backup encryption and privacy procedures. Before provider execution, verify provider-specific idempotency and reconciliation. All live actions stay disabled.

## Ingress and interruption verification

The example deploy/public-webhook.nginx.conf serves TLS on 8443 and exposes only the signed order webhook. Its IP and global limits are provisional and must be tuned to verified traffic and trusted proxy configuration. All console/internal routes return 404 at this public boundary. Use a separate private HTTPS operator ingress with identity controls, never expose n8n's editor, and configure Uvicorn to trust forwarded headers only from a known proxy address. Use trusted real certificates in actual staging. Do not use the generated CI certificate or expose the Compose API port publicly. App mutation concurrency is capped per process and body reads have a 15-second deadline; edge controls still matter for multiple processes and slow connections.

CI runs an isolated ingress smoke test (including a bounded synthetic request burst), pauses n8n and restarts the API with a durable queued record, observes scheduled recovery, interrupts the database, checks liveness/readiness, and restores a disposable dump. It also runs Chromium/axe against the isolated synthetic preview, gating selected structural rules and retaining the complete automated violation report. Review the full report; manually verify screen readers, focus order, contrast, role-specific workflows, zoom and keyboard completion. Automated reports are not accessibility conformance certification.

For representative performance, use the existing benchmark for in-process database/service measurements and the scheduled interruption exercise for observed recovery duration, which includes the deliberate outage. Neither measures sustained production network load. Before increasing worker concurrency or batches, measure arrival rates, p95 queue age, retry traffic, backlog drain, query plans and database saturation under a disposable representative workload.

Run `python -m scripts.privacy_inventory --older-than-days 90` from the authorized deployment terminal to obtain a read-only aggregate retention inventory. The threshold is a reporting parameter, not a default retention policy. Do not delete historical approvals, payloads or audit evidence until retention and replay obligations are resolved. Container Uvicorn access logs are disabled because the application records sanitized route templates, status, duration and correlation IDs; review gateway/error logs separately.
